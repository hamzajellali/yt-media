## 1. Choose the video with vidIQ, then make it
The user wants vidIQ (tools `mcp__vidIQ__*`, load with ToolSearch) to decide what to make while its free credits last
(asked by the user in a live session on 2026-11-24; this replaces "least recently used kind", which is now only the
fallback when the queue below is empty).
Read `VIDIQ.md` (research so far) and `vidiq_plan.json` (ordered queue) first.
a. `vidiq_balance` (free). If totalCredits >= 5, do research before choosing, 5 credits per call, at most 4 paid calls
   (20 credits) per run so the monthly free credits last across runs (never pay for credits, never upgrade the plan):
   - `vidiq_user_channels` (free) must list Gravity Candy (UC6jSQGEwcejJGjanTUUb-rw); the vidIQ account is
     pondokarfouli456@gmail.com (free plan, 150 credits/month, renews on the 24th). First spend 5 on
     `vidiq_channel_videos` (channelId UC6jSQGEwcejJGjanTUUb-rw, videoFormat short) to see views/likes/VPH of each of
     our Shorts by kind. `vidiq_channel_analytics` (retention, traffic) only once YouTube Analytics has data for the
     dates asked (it lags 2–3 days; an empty result still costs 5).
   - `vidiq_outliers` (contentType short) / `vidiq_trending_videos` (videoFormat short, sortBy recentVph) on our niche
     or on the concept at the top of the queue; `vidiq_score_title` to compare 2 title options.
   Write the findings (dated, with numbers as vidIQ returned them) into `VIDIQ.md` and reorder/extend the queue.
b. Take the first entry of `vidiq_plan.json` `queue` (kind, optional song, optional guess). Move it to `done` with the
   date and the video link after upload. If the queue is empty, pick the kind used least recently in `log.csv`.
   Kinds: grow multiply escape lines race speed. `--song` / `--guess` only work with grow and lines
   (songs: see MELODIES in the engine; Christmas songs: Jingle Bells, Deck the Halls, We Wish You a Merry Christmas).
   After 25 December drop Christmas songs from the queue.
Seed = YYYYMMDD as an integer (+1, +2... if that seed is already in log.csv).
```
cd /home/claude/gc/engine
python3 gc_engine.py short --seed SEED --kind KIND [--song "SONG"] [--guess] --out /tmp/v.mp4 --meta /tmp/v.json
python3 gc_engine.py long  --seed SEED --minutes 8.5 --out /tmp/v.mp4 --meta /tmp/v.json   # long videos
```
`--guess` = guess-the-song mode: the screen says GUESS THE SONG, the title asks "Can You Guess the (Christmas) Song?",
and the answer is revealed only at the end. Don't put the song name in the title or description of a guess video.
QA before uploading: `ffprobe` duration > 8 s (short) or > 7 min (long); extract 3 frames
(`ffmpeg -ss T -frames:v 1`) and look at them with Read: simulation visible, text readable, no stray lines.
Check the audio is not silent (`ffmpeg -i /tmp/v.mp4 -af volumedetect -f null -`, mean_volume > -40 dB).
If the title in v.json is a duplicate of a title in log.csv, re-render with seed+1.

## 3. Upload through the Claude desktop app's built-in browser
Tools `mcp__remote-devices__Claude_Browser__*` (load the built-in-browser skill first). The browser is already
signed in to the channel. Never type passwords; if signed out, stop and report.
IMPORTANT: the browser holds several Google accounts; Gravity Candy is under **authuser=3** (checked 2026-11-22).
Add `?authuser=3` (or `&authuser=3`) to EVERY studio.youtube.com URL. If a page says "you don't have permission"
(HTTP 403), find the right index with javascript: fetch `https://studio.youtube.com/channel/UC6jSQGEwcejJGjanTUUb-rw?authuser=N`
for N=0..5 and use the one that returns 200; note the new index in your report.
1. `preview_start` https://studio.youtube.com/channel/UC6jSQGEwcejJGjanTUUb-rw/videos/upload?d=ud
2. javascript_exec (wait ~3 s first):
```js
const blob = await fetch('https://raw.githubusercontent.com/hamzajellali/yt-media/gc-drop/gc_SEED.mp4').then(r=>r.blob());
const f = new File([blob], 'gravity_candy_SEED.mp4', {type:'video/mp4'});
const inp = document.querySelector('input[type=file][name=Filedata]');
const dt = new DataTransfer(); dt.items.add(f); inp.files = dt.files;
inp.dispatchEvent(new Event('change', {bubbles:true}));
```
3. `find` "textbox" → title box ("Add a title...") and description box ("Tell viewers..."). For each: `scroll_to`,
   `left_click` the ref, `ctrl+a`, then `type` the text from v.json. Verify with
   `[...document.querySelectorAll('ytcp-uploads-dialog #textbox')].map(t=>t.innerText)`.
4. Long videos only: thumbnail — fetch the staged PNG the same way into
   `document.querySelector('ytcp-uploads-dialog input[type=file][accept*="image"]')` (if not found, skip and report).
5. Audience: click `tp-yt-paper-radio-button[name="VIDEO_MADE_FOR_KIDS_NOT_MFK"]`, verify it has `checked`.
6. Click `ytcp-uploads-dialog #next-button` 3 times (2.5 s apart). If the Checks step reports a copyright
   or other issue, stop, leave it private, report.
7. Click `tp-yt-paper-radio-button[name="PUBLIC"]` (verify aria-checked=true), then `#done-button`.
   If a "Video uploading" dialog appears, DO NOT navigate away: poll every ~20 s (javascript_exec with a
   short setTimeout, each call under 40 s) until the upload finishes, then read the link from the
   content page (`/videos/upload` list, first row) or the "Video published" dialog.
   Big files: the fetch() of a long MP4 can take >45 s and time out the tool call; that is fine — wait
   30 s and check `document.querySelector('ytcp-uploads-dialog')` before retrying (never upload twice).
   Thumbnail input for long videos: `ytcp-uploads-dialog ytcp-thumbnail-uploader input[type=file]`.
   Long videos are encoded at crf 25 so files stay under GitHub's 100 MB limit; if a file is still
   over 95 MB, re-encode with `ffmpeg -i v.mp4 -c:v libx264 -crf 28 -preset veryfast -c:a copy v2.mp4`.

## Rules
- Original content only (this engine). No copyrighted music, characters or footage.
- Every video must differ (different seed/kind); never re-upload the same file.
- If the browser/desktop app is unreachable, still render and stage the video, add a log row with link `PENDING`,
  and report. The next run uploads PENDING rows first (oldest first, max 2).
